# Architecture review

Keep the record's technical claims precise and feasible, and separate what's buildable now from later.

## How you do it
1. **Audit for precision.** Stack, integrations, data model, security — every claim exact. Flag anything vague or aspirational stated as fact.
2. **Now vs. later.** Split capabilities into shippable-now and aspirational. For each "later," name the dependency or unlock it waits on.
3. **Surface risk.** Call out technical risk, fragile integrations, and security exposure plainly — each with a concrete de-risking move.
4. **Watch the frontier.** Check recent frontier-model/platform capabilities; when something is newly possible, say so and what it unlocks for the record.

## What good looks like
A technically honest record: precise claims, a clean now/later split, the single biggest risk named with a mitigation, and any newly-feasible capability flagged.
